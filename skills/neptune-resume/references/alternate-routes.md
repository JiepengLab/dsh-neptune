# 电脑晚上不能开机

**学生的电脑晚上关着，因为宿舍断电。** 这是常态，不是例外。

插件跑在用户的电脑上。六点那会儿电脑得开着，续充才有人执行。

**电脑早上才开机时，宿主会补投那条过期的任务。** 但那是八九点甚至更晚。
⇒ **补投不算「六点充上」** ⇒ **这种场景 DSH 任务不是解法，不要建。**

## 路一：上游的 GitHub Actions

**跑在云上。断电断网都不影响它** ✓ 这是断电场景最稳的一条。

**怎么做**

1. Fork `Lucent-Snow/neptune-auto-charger`。
2. 在仓库的 Settings → Secrets 里配三个：`NEPTUNE_OPEN_ID`、`NEPTUNE_AREA_ID`、
   `NEPTUNE_EMPLOYEE_ID`。
3. 启用仓库里那个 workflow。它每半小时跑一次，从 02:47 到 06:07 北京时间。
   落在可充时段里的那次是 06:07。

**代价**

- 凭证进 GitHub Secrets。要有 GitHub 账号。
- 它每天到点就续，不看昨晚有没有断电单。

**怎么拿到那三个值**

- `NEPTUNE_AREA_ID` 固定是 `6`。
- `NEPTUNE_OPEN_ID` 与 `NEPTUNE_EMPLOYEE_ID` 用 `neptune_recipe` 写进剪贴板，再粘进去。
  插件不把值贴进聊天。写之前它会先问用户。

## 路二：手机自动化

**手机在宿舍一直开着，电断了也有电。** 要确认的是六点那一刻手机还能连网。

**怎么做**

1. 取到配方网址。用 `neptune_recipe` 写 `url`，起单网址进剪贴板。
2. 在手机自动化里加一个「打开 URL」的动作，把剪贴板里的网址填进去，定在 06:05。

**配方网址的来处**

**它是插件拼的。** 厂商小程序那个扫描页面上没有它。
`wxscan/<桩号>` 跳过去是厂商的落地页，那页的网址上只有 openId、areaid、
employeeid、accountmoney。

**写进剪贴板之前插件会先问用户。** 网址带凭证，插件不贴进聊天。

**代价**

- **这条网址没有闸门。** 不查插座占用、不查余额、不查昨晚有没有断电单。
- 网址带 openId，**它是持有者凭证**，拿到就能用用户的余额起单。
  **别贴进聊天，别截图。**
- 只在「车一定停在那个插座」时安全。厂商不拦在别人占用的插座上起单。

## 怎么跟用户说

先说一句为什么 DSH 任务不行：**电脑夜里关着，早上补投也到不了六点**。
再把两条的代价摆出来让他挑。

**不要建完 DSH 任务再解释这一条。** 先问，再决定。

**这两条都不需要人守在六点。** 不要拿「手动敲命令」当替代，
那要求用户六点醒着，正是断电场景做不到的事。
