# 尼普顿续充

给 agent 的流程与硬规则。用户要查充电状态、要续充时用。

## 什么时候用

用户要查充电状态、要续充、要定一个明早续上的任务。

**「小龟」就是电瓶车。** 用户说「看看小龟充电情况」，问的是这辆电瓶车的充电状态。

## 照表选工具

| 用户要的 | 调哪个 |
|---|---|
| 查余额、当前订单、可充时段、最近一单 | `neptune_status` |
| 某根桩哪些插座空着 | `neptune_sockets` |
| 取凭证（第一次用） | `neptune_pair` |
| 读插座二维码照片上的桩号与插座号 | `neptune_scan` |
| 定一个明早续上的任务 | `neptune_charge_at` |
| 到点执行续充 | `neptune_charge`。**只在宿主投递那条任务时用** |
| 把账号信息或起单网址交给用户 | `neptune_recipe`。**先问过用户再调** |

**每件事都有工具。调工具，不要自己写代码去问厂商接口。**

## 凭证

openId 就是凭证。它只存在插件内存里，像环境变量那样只有插件自己读得到。

- **不得暴露它。** 不打印，不写进任何输出、文件、总结、任务提示。
- 工具返回的内容已经打码。要状态就读状态，不得自己去取 openId。
- 插件卸载，凭证就没了。

## 取凭证

`neptune_pair` 拿凭证。三个来路：

1. **环境变量**。`NEPTUNE_OPENID` 是 openId 本身，或整条配对串
   `zju-neptune:v1:<openId>:<areaid>`。串里的 areaId 是发给厂商的校区号，
   它优先于 `NEPTUNE_AREAID`。openId 本身不分校区，一个号能看到所有校区的单。
2. **调用方给的目录**。`neptune_pair` 的 `dir` 参数。插件自己去那儿读 History 文件。
3. **挖本机微信浏览历史**。插件先试几个候选路径，再在微信的数据根目录下面扫
   `History` 文件。openId 只落在**电脑微信的浏览器**里。

**插件说没找到时**：先用文件工具找微信的数据目录，把路径喂给 `dir` 再试一次。
要找的结构是 `…/radium/web/profiles/<档案名>/History`，喂**上面那一层**的 profiles 目录。

**只列目录名，不得读文件内容。** History 文件里有 openId。
读它的内容就等于把凭证放进了上下文、会话日志和模型请求体。

也可以让用户在**电脑微信**里打开 `https://szlzxn.cn/wechat/wxscan/50959120`，
末尾那串 8 位数字换成他自己那根桩的编号（编号印在桩上）。
等它跳完，再跑一次 `neptune_pair`。落地页打不开是正常的，厂商那台主机已经不用了。
那条网址已经进浏览历史。

**别试图从手机上拿那条网址。** 微信不给你复制。实测六条路全堵死：
⋯ 菜单复制网址、发给文件传输助手、长按标题弹网址、选中页面上的 openId 文字、
复制到系统浏览器、非微信浏览器做授权。

**传整个数据根目录，不得只传某一个 `profiles` 目录。**
企业微信（WXWork）也有 `radium\web\profiles`，
按名字搜第一个命中的很可能是它，那儿没有厂商的网址。

Windows 上大致在 `%APPDATA%\Tencent` 下面（个人微信是 `xwechat`，
企业微信是 `WXWork`），找 `radium\web\profiles`，每个档案目录里有一个 `History`。
macOS 在 `~/Library/Containers/com.tencent.xinWeChat` 下面，版本目录名带版本号。

把含有 `Tencent` 或 `com.tencent.xinWeChat` 的那一层交给 `neptune_pair` 就行。
插件自己扫目录、读文件、取出凭证，全程不外泄。
扫一遍本机的 `%APPDATA%\Tencent` 约两百毫秒。

## 流程

**第 0 步，先问一句：这台电脑凌晨六点能开着吗。**

这条要最先问，问完再往下做。

**宿舍晚上断电是常态，不是例外。** 学生电脑晚上关着、睡着，
因为宿舍到点断电。所以这一问的答案通常是「不能」。

| 答案 | 怎么做 |
|---|---|
| 能（电脑一直开着） | 走下面的步骤，建 DSH 任务 |
| 不能（宿舍断电、要关机睡觉） | **不要建 DSH 任务。** 先查状态与插座（只读，做了不花钱），然后给两条真正六点准点的路。见下面「电脑晚上不能开机」 |

**「早上六点充上」是硬要求。** 电脑早上才开机时，宿主会补投那条过期任务，
但那是八九点甚至更晚，不是六点。⇒ **补投不算数** ⇒ **不能开机的场景 DSH 任务不是解法**。
⇒ **不要建完 DSH 任务再跟用户解释这一条。** 先问，再决定建不建。

1. 先跑 `neptune_pair`。取不到就照它给的下一步做。
2. 查状态用 `neptune_status`。看某根桩的插座用 `neptune_sockets`。
3. **续充只有一条路：定到点。** 晚上或凌晨说「帮我续充」，就是早上六点那一单。
   用 `neptune_charge_at`，不给时刻就定在 06:05（设备可充时段 6:00 开始之后五分钟）。
   **当场续这条没有了。** 用户说「现在就充」，就告诉他现在在窗口外
   （设备说 6:00 到 24:00），并起一个 06:05 的任务。
   **「白天」「下午」这类说法要问用户几点。**用户说过「跟上次一样」就照上一单的开始时刻。
4. 目标默认是**最近一单真正充过电的**那个桩与插座。用户指定别的就用他指定的。
   **用户拍了插座上二维码的照片**：用 `neptune_scan` 读它。
   **把附件的路径直接给它。**不用先把照片复制到工作目录。
   **二维码优先。**它是机器读的，照片上那行印刷编号是人看的，可能看错。
   编号前 8 位是桩号，后 2 位是插座号（如 5095912011 是桩 50959120 的 11 号插座）。
   你也读了照片上那行印刷编号的话，把它作为 `label` 传进去。
   两者不一样时工具会说，以二维码为准。
   它还会向厂商核一遍那个插座在不在，读糊了当场就知道。
   读出来填进 `neptune_charge_at` 的 `devaddress` 与 `port`。
   过了午夜小程序起不了单，设备断电。这时只能靠照片把下一单定好。
5. 起完任务就说两件事：到点会叫醒 agent，消耗一点 token。
6. 拿不准就先 `dry_run` 演练。它只判断不动作。

**到点执行时会发生什么，插件自己判断，你不用管。**
宿主把任务提醒投回会话，提醒里带着续哪个桩哪个插座。
那时候插件只续**昨晚被午夜断电切掉的那一单**，手动结束的、车已经不在的不续。
插座占不空、余额够不够，插件自己查。
**投递叫醒的那次调用已经有人批准过，不得再问。**

## 定时任务会消耗 token，要跟用户说

**DSH 任务那条路要 agent 对话。** 到点宿主把任务提示投进会话，agent 醒过来执行续充，
这一轮对话消耗 token。

⇒ **起任务时把这件事说给用户。** 一句话就够：「明早六点那个任务到点会叫醒 agent，
会消耗一点 token」。
⇒ 用户不在意就不用多解释 ✓

## 电脑晚上不能开机

**学生的电脑晚上关着，因为宿舍断电。** 这是常态。

**DSH 任务要求电脑六点那一刻开着。** 它做不到。⇒ **别建。**

**真正六点准点的是这两条**：

| 路 | 六点准点吗 | 怎么用 | 代价 |
|---|---|---|---|
| **上游的 GitHub Actions** | **准**，跑在云上 | Fork 那个仓库，配三个 secret | 要 GitHub 账号，凭证进 Secrets |
| **手机自动化** | **准**，手机一直在 | 加一个「打开 URL」的动作，定在 06:05 | 网址带凭证，且要手机在六点能连网 |

**不要拿「手动敲命令」当替代**，那要求用户六点醒着。

两条的完整做法读 `references/alternate-routes.md`。

**给用户的说法**：先说清楚为什么 DSH 任务不行（电脑夜里关着，补投也到不了六点），
再把这两条摆出来让他挑。**不要建完 DSH 任务再说这个。**

## 硬规则

- **不得自己读微信 History 文件的内容。** 取凭证那一节有这条。
  凭证进了上下文，就进了会话日志与模型请求体，撤不回来。
- **不得为了找工具去列插件。** 插件注册了什么，这份技能里写全了。
  找不到就说找不到。
- **断电那条支路只读 `references/alternate-routes.md`。** 不要上网找上游仓库，
  不要去别的会话里找遗留的脚本。
- **往剪贴板写之前先问过用户。** `neptune_recipe` 会把值写进用户的剪贴板。
  先告诉用户写什么、为什么写，等他同意再调。用户没要那个值，就不要动他的剪贴板。
- **不要去读插件的源码、README 或目录结构。** 这份技能里的规则就是全部。
- **不要自己写代码去问厂商接口。** 每件事都有工具。
- **不要把剪贴板里的值读回来。** 值进了剪贴板就完了。不要贴进聊天，不要写进文件。
- **结束方式看工具报的那句话。**`neptune_status` 会写清是哪种结束。
- **余额不够预扣时插件会跳过。**预扣是设备定的，一元或两元。
  报的是「余额不够预扣」，不是「余额为 0」。告诉用户充多少。
- **起单前插件会查插座占用。** 厂商不拦在别人占用的插座上起单，
  结束订单还会把那个插座的状态清掉，等于打断对方的充电。
- **营业时间是厂商强制的。** 窗口外起单会被厂商结束，充不上。
- **厂商对连续起单有限流**，会回「系统繁忙，请2分钟后操作！」。
  那是限流不是失败，不要重试。
- **车在不在只有人知道。** 续充的前提是车还在那个插座上。
